# 제출용 프로젝트의 범위

## 현재 증명하는 역량

- 기존 코드의 평가 누수를 발견하고 학습·검증 경계를 수정했다.
- 데이터 불균형, 고차원 입력, 모델 선택 변동을 실험으로 비교했다.
- 좋은 결과와 나쁜 결과를 모두 저장하고 시간순 일반화의 한계를 드러냈다.
- 예측·후보 설명·저장·조회·경보 확인을 실행 가능한 흐름으로 연결했다.
- 코드 검사·테스트·컨테이너·CI로 실행 근거를 제공한다.

## 증명하지 않는 것

- 삼성전자나 SK하이닉스의 특정 채용 기준 충족 또는 합격 가능성.
- 실제 반도체 공정 전문성, 양산 배포, 수율 개선, 실시간 대용량 운영.
- 익명 센서의 물리적 불량 원인 또는 보정된 불량 확률.

## 제출 전 본인이 설명할 내용

1. 왜 test를 이미 본 이후의 v2를 신규 독립 검증이라고 할 수 없는가?
2. 데이터가 늘어난 효과와 알고리즘 변경 효과를 왜 분리할 수 없는가?
3. CV 평균 AP와 OOF F2를 각각 어디에 사용했는가?
4. 경보 비율 30%는 왜 test나 미래 데이터에서 보장되지 않는가?
5. 원인 후보와 인과적 원인은 어떻게 다른가?
6. 시간순 성능이 낮은 상황에서 무엇을 추가 검증해야 하는가?
7. API 한 번 호출하면 네 테이블 중 어떤 기록이 생성되는가?

면접에서는 기능을 나열하기보다 문제 발견 → 설계 판단 → 실험 근거 → 한계 → 다음 검증 순서로 설명한다. AI 도구를 활용한 부분을 숨기지 않고 이해하지 못한 설계를 독자적 성과로 주장하지 않는다.
